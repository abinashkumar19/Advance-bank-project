Defense in depth

Five walls between
the internet and your money.

No single layer is trusted alone. A request has to clear all five before it ever touches an account balance.

The five layers, in order

Each layer only trusts what already passed the one before it.

01

Edge protection

AWS WAF + ALB

Traffic hits a web application firewall before it reaches any service — rate limiting and common exploit patterns are blocked before they're ever seen by the app.

02

Network isolation

Private VPC subnets

Every service runs in a private subnet with no direct route to the internet. Only the load balancer is public — the database, cache, and search cluster never are.

03

Cluster boundaries

Amazon EKS

Each of the twenty services runs as its own isolated workload, so a bug in one can't reach into another's memory or credentials.

04

Scoped identity

IAM Roles for Service Accounts

A service only gets the exact AWS permissions it needs — the cards service can't read the fraud-detection queue, and nothing holds a long-lived static key.

05

Data at rest

Encryption + point-in-time recovery

Every table and volume is encrypted at rest, with continuous backups — so even in the worst case, nothing is unrecoverable or unencrypted.

What that means in practice

AUDIT-LOG

Every action is recorded

Account changes, transfers, and admin actions all write an immutable entry — visible to you, and never editable after the fact.

FRAUD-DETECTION

Screened without delay

Transactions are screened asynchronously, so a fraud check never holds up a payment you're waiting on.

KYC

Verified before funded

Identity is verified before an account can move money — not after.

DISPUTES

A paper trail either way

Every dispute keeps its full history, so you can always see exactly what happened and when.
